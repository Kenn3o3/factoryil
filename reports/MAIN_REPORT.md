### 4.2 What is actually randomized (implementation details)

This section is grounded in the current implementation of:

- `factoryil.runner` (maps CLI/YAML `rand_*` scalars to config fields):
  - [src/factoryil/runner.py](../src/factoryil/runner.py)
- `FactoryILEnv._reset_idx` (applies the noise during reset):
  - [src/factoryil/env/factory_env.py](../src/factoryil/env/factory_env.py)
- Noise fields + default semantics (config docs):
  - [src/factoryil/env/factory_task_cfg.py](../src/factoryil/env/factory_task_cfg.py)

#### Distribution

All reset-time *position* noise is sampled i.i.d. per-axis from a uniform distribution:

- For a configured per-axis max-noise vector `noise = [nx, ny, nz]`, the sampled offset is:
  - `delta[i] ~ Uniform(-noise[i], +noise[i])` for `i ∈ {x, y, z}`

This applies to:

- Hole (fixed asset) position noise: `fixed_init_pos_noise`
- Peg (held asset) position noise: `held_init_pos_noise` (world-frame or gripper-frame depending on spawn mode)
- End-effector (EEF) position noise: `eef_init_pos_noise` (applied via one DIK step)

#### Axis mapping (important)

In the current `factoryil.runner` implementation, the YAML/CLI scalars are **not** expanded to XYZ equally; they are mapped to specific axes:

- `rand_eef = v`  → `env_cfg.eef_init_pos_noise = [v, v, 0.0]`
- `rand_hole = v` → `env_cfg.fixed_init_pos_noise = [v, v, 0.0]`
- `rand_peg = v`  → `env_cfg.held_init_pos_noise = [v, 0.0, 0.0]`

Implication: the baseline runs randomize primarily in-plane (XY) for EEF/hole, and along a single axis for the peg.

Also note: the CLI help text in [src/factoryil/cli.py](../src/factoryil/cli.py) describes `[v, v, v]` expansions, but the mapping above (from `runner.py`) is what is actually used when running the experiments.

#### Frames + ordering (where the noise is applied)

During reset (`FactoryILEnv._reset_idx`):

1) **Hole (fixed asset) position**
   - Base pose comes from `cfg.init_assets.fixed_pos` / `fixed_rot`.
   - `fixed_init_pos_noise` is applied in the **world frame** to the fixed asset translation.
   - Fixed asset orientation is not randomized (always `cfg.init_assets.fixed_rot`).

2) **Robot initial joint pose**
   - Arm joints are reset to `cfg.init_robot.joint_pos`.
   - Fingers are set closed so the peg can be grasped.

3) **EEF position noise (via one Differential IK step)**
   - `eef_init_pos_noise` is sampled in the **world frame** and applied as a *translation-only* delta pose.
   - This is executed as a one-shot DIK update before the peg is spawned in the gripper.
   - The translation is clamped by the DIK max per-step translation limits (`cfg.ctrl.max_pos_delta`), but for the current magnitudes (e.g. 0.05 m) this clamp should not bind.

4) **Peg (held asset) position noise**
   - Default `cfg.init_assets.spawn_in_gripper = True` (see `InitAssetsCfg`), so the peg is typically spawned already grasped.
   - If `spawn_in_gripper=True`:
     - `held_init_pos_noise` is sampled and applied in the **gripper/fingertip frame** by perturbing the peg’s desired relative position to the gripper.
     - The peg world pose is then computed from the (potentially EEF-noised) fingertip pose.
   - If `spawn_in_gripper=False`:
     - `held_init_pos_noise` is applied in the **world frame** to the peg’s initial world translation.

#### What is *not* randomized (in the current code)

- Hole (fixed asset) orientation: not randomized.
- Peg (held asset) orientation: not randomized in the current `FactoryILEnv._reset_idx` path.
  - The config includes `held_init_rot_noise`, but it is not applied in the current reset implementation.
- EEF orientation: not randomized; only a translation delta is applied.

## 7) Immediate takeaways (initial)

- `equibot` is best on 3/4 attached evaluations (peak 69% success).
- `dp_rgb_cam_tl_tr` is best on `RAND_PEG_EXPERIMENT` (62%), outperforming `equibot` there.
- Performance varies strongly with environment randomization regime.
- Potential mismatch to double-check: whether `rand_eef` was used during *collection* for `MAIN_EXPERIMENT_1/2` datasets, since it is used during evaluation.
